# Two-step task

Package: `@jspsych-timelines/two-step-task` ([source](https://github.com/jspsych/jspsych-timelines/tree/main/packages/two-step-task)). Version documented here: <code>{manifest['two-step-task'].version}</code>.

## Overview

The two-step (two-stage) Markov decision task separates model-based from model-free control of choice. On each trial the participant makes two choices. The first choice, between two options, usually leads to one of two second-stage states and sometimes to the other. In the second stage they choose between two options, and the chosen option pays a coin with a probability that changes slowly over the task. A model-free learner repeats a first-stage choice that was just rewarded, whatever the transition. A model-based learner uses the transitions: after a rare transition a reward says the *other* first-stage option is the better route to that state. The usual measures are the probability of repeating the first-stage choice by previous reward and transition, a model-free index (the effect of reward), a model-based index (the reward by transition interaction), and, in hybrid reinforcement learning models, the weight `w` on the model-based values.

The defaults follow the Expfactory two-stage-decision task (S024 in the spec): 50 practice trials, 200 test trials in 2 blocks, 70% common transitions, 2000 ms for each choice, abstract symbols, a reward walk with SD 0.025 inside 0.25 to 0.75, and a 1000 ms highlight of each choice. Studies differ most in the number of trials, the transition probability, the reward walk and how much of the structure the instructions disclose, so the package has options for all of them.

**Canonical citation:** Daw, N. D., Gershman, S. J., Seymour, B., Dayan, P., & Dolan, R. J. (2011). Model-based influences on humans' choices and striatal prediction errors. *Neuron, 69*(6), 1204-1215.

## Task Description

**A trial.** An optional fixation (`fixation_duration_ms`, 0 by default). Two first-stage options appear, left and right (by default two abstract symbols; `stimulus_set: utils.stimuli.spaceshipPlanetAlien` draws a rocket and a flying saucer). The participant presses the left or the right key within `response_window_ms`. The chosen option is highlighted (`response_acknowledgement_ms`). The screen then changes to one of two second-stage states, a red one or a blue one, which the first-stage option usually leads to (`common_transition_prob`): option A to red, option B to blue. Two second-stage options appear, and the same two keys choose one. The chosen option is highlighted, and the outcome (a coin or no coin) is shown for `feedback_duration_ms` with the running total of coins (`running_score_display`). After `iti_ms` the next trial starts.

**There is no correct answer.** Rewards are random. Nothing in the data says that a choice was right or wrong, and the package writes neither `correct` nor `correct_response`. What the task measures is how the choice depends on what happened before.

**Pictures and cover story.** `stimulus_set` takes a stimulus set, which is data: the pictures in their roles and the words the instructions use for them. The package's bundled sets are values in `utils.stimuli`, and your own set is the same shape. One option holds both, so the story always matches the pictures.

| Set | Pictures | Words |
|---|---|---|
| `utils.stimuli.abstractSymbols` (default) | A ring and a cross; on the red screen a circle and a square, on the blue screen a triangle and a diamond; a coin | symbol, screen, coin; "the ring", "the red screen" |
| `utils.stimuli.spaceshipPlanetAlien` | A rocket and a flying saucer; two aliens on each of a red and a blue planet, with the planet's curve along the bottom of the display; a coin | spaceship, planet, alien, coin; "the rocket", "the red planet" |

Both are simple drawings written for this package (MIT, like the package; the licence is a `@license` comment in `src/drawings.ts` and in the bundle). They stand in for the studies' own pictures: Expfactory's own abstract symbols (S024) and the spaceship and alien pictures of the Kool and Niv lab jsPsych tasks (S025, S026) are not bundled, and the study presets say so. The other cover stories of the literature (`magic_carpet_mountain_genie`, S033, S120; `ship_island_chest`, S047) have no bundled set; pass your own.

Your own set:

```ts
{
  name?: string,                                // recorded as stimulus_set (default "custom")
  noun?: { first?, second?, state?, reward? },  // each { singular, plural }
  first_stage: [A, B],                          // two items
  states: [                                     // the state A usually leads to, then the one B usually leads to
    { items: [option_1, option_2], id?, name?, picture?, background?, foreground?, color?, horizon? },
    { items: [option_1, option_2], ... },
  ],
  reward?: { rewarded, unrewarded },            // the outcome pictures (default: a coin, an empty slot)
  background?, foreground?,                     // colours of the first-stage screens
}
```

An item is a string (a text item) or an object with one of `text`, `image` (a URL) or `svg` (SVG markup), an optional `id` and, for a first-stage item, an optional `name` ("the north market"), which the instructions use. A state's `name` names it in a sentence, `picture` shows it in the questions about where each option leads (default: a square in `color`), `background` and `foreground` colour the display on its screens, and `horizon: true` draws a planet's curve in `color`. The nouns default to "picture" (or "word" for text items), "screen" and "coin"; the names to "the first picture" and "the second screen". Ids default to the text, or the set's name and the role (`custom-first-1`, `custom-state-2`, `custom-state-2-option-1`). Duplicate ids throw, as do a pair that is not two items, an item with two kinds and a colour that is not a CSS colour. The roles keep their names in the data and in `reward_probability`: `A` and `B`, `red` and `blue` (the first and the second state, whatever their colour), `option_1` and `option_2`; the set's own ids are recorded beside them.

**The schedule.** Everything that is generated is drawn when `createTimeline` is called, through `jsPsych.randomization`, so a seeded run has the same schedule whatever the participant (or a simulated participant) chooses: the common or rare transition of each trial, the reward probability of each of the four second-stage options (a Gaussian random walk from a starting value), whether each option would pay a coin on that trial, which option is on which side, and jittered durations. The probabilities are recorded on every trial (`reward_probs`), so analyses can use the true values (S009's correction to the stay analysis needs them). Practice has its own walk. A trial that is missed keeps its place in the walk: with `missed_response_handling: "skip_trial"` the walk moves on, with `"repeat_trial"` the same trial is run again, with the same probabilities and outcomes.

### Reward schedule

`reward_schedule` is a typed object. Only `kind: "random_walk"` is implemented; the other kinds of the spec (`block_alternating`, `pregenerated_walk_sets`) throw when the timeline is built.

```javascript
reward_schedule: {
  kind: "random_walk",
  sd: 0.025,               // SD of the Gaussian step, per trial and option
  bounds: [0.25, 0.75],    // lower and upper limit
  boundary: "reverse_step" // or "reflect"
}
```

The two boundary rules differ at the limits. `reflect` folds a step that would cross a limit back inside (Daw et al., 2011; S025, S029, S047): from 0.74, a step of +0.03 gives 0.73. `reverse_step` takes the step in the opposite direction instead (Expfactory, S024): from 0.74, a step of +0.03 gives 0.71. The default is the anchor's (`reverse_step`), although four of the five walks in the spec reflect.

`reward_probability` sets the starting values by state (`red`, `blue`) and option (`option_1`, `option_2`): a number, or `{ min, max }` for a uniform draw once per run. The default draws all four uniformly from 0.25 to 0.75. Starting values must lie within `reward_schedule.bounds`.

```javascript
// Kool et al. (S025): one state starts at 0.25 / 0.75, the other at 0.4 / 0.6; Daw et al. walk (reflect)
createTimeline(jsPsych, {
  reward_probability: { red: { option_1: 0.25, option_2: 0.75 }, blue: { option_1: 0.4, option_2: 0.6 } },
  reward_schedule: { kind: "random_walk", sd: 0.025, bounds: [0.25, 0.75], boundary: "reflect" },
});
```

### Counts

`n_test_trials`, `n_blocks` and `trials_per_block` must agree: give any one and the others follow (from the defaults of the rest), give two and the third follows, give all three and they must satisfy `n_test_trials = n_blocks * trials_per_block`, otherwise the timeline throws. When `n_test_trials` does not divide evenly, the blocks differ by one trial, and `trials_per_block` is the size of the largest. Practice is one block of `practice_trials`.

### Missed choices

A choice not made within `response_window_ms` is a missed trial. The "too slow" message is shown for `timeout_message_ms` and the trial ends. `missed_response_handling` says whether it is skipped or repeated. A repeated trial that is missed again is repeated up to 5 more times and then skipped (a package constant: without a limit, a participant who never answers would be shown the same trial for ever). Missed trials are recorded (`missed`, `missed_stage`), and the package never stops the task for missed trials. The literature's abort after N missed trials (S026) is a data-quality rule, and so are the exclusion criteria below.

### Instructions

The instruction pages are followed by an interactive walkthrough (`instruction_demonstration: "interactive"`, the default). A task without a correct answer has nothing to repeat until correct, so the steps ask for what the pages just said, using the task's own screens and keys:

1. a scripted first choice (the option on the left, pressing the left key), then the screen of the state it led to;
2. a scripted second choice (the option on the right), and the coin it gives;
3. by `contingency_disclosure`: `full`: for each first-stage option, which state it usually leads to (the two states are shown, one on each side, and the answer alternates between the sides); `partial`: whether a first-stage option always goes to the same state, or usually but not always (two sentences, one on each side); `none`: nothing;
4. for `partial` and `full`: whether the reward chances of the second-stage options stay the same or change slowly.

A wrong answer shows a hint and repeats the step, up to 3 attempts, after which the answer is shown and the walkthrough moves on. Rows are `part: "instruction_check"` (with `step`, `correct` and `attempt`) and `instruction_feedback`; they are never scored. The page before practice says that trials now run at the real pace and that the main task follows.

`contingency_disclosure: "partial"` (told that each option mostly leads to one state, not which) is the default. The walkthrough shows one scripted transition, so a participant sees one option lead to its state before practice. `full` also tells which state each option usually leads to, and checks it. `none` tells only the keys and that coins are the reward.

### Questionnaire

`manipulation_check: "questionnaire"` asks, after the main task, for each first-stage option which state it mostly led to (`part: "manipulation_check"`, with `answer`, `common_state` and `correct`).

### Simulation

Under `jsPsych.simulate([task], "data-only")` the package uses a hybrid reinforcement-learning participant: model-free first-stage values (TD(1)) mixed with model-based values by a weight `w`, softmax choice, one learning rate, ex-Gaussian RTs, and a slower second-stage RT after a rare transition. Its stay pattern is the expected one (a model-based learner has a positive model-based index, a model-free learner a positive reward effect). A global forced RT (`{ default: { data: { rt: 400 } } }`) wins over the model, and the choices are then random. Set the parameters with `utils.simulation.setSimulatedAgent({ w: 1, alpha: 0.5, beta: 6 })` (`null` restores the defaults). It affects only simulated runs.

## Data Output

Every row carries `task: "two-step-task"` and `task_version`. A trial has two kinds of rows. **The `response` row** (`part: "response"`, one per trial attempt, written after the last display of the trial) is the scorable row and carries everything an analysis needs. The **`choice` rows** (`part: "choice"`, one per stage) are the raw record of each key press.

| Field | Type | Description |
|---|---|---|
| `phase` | string | `"practice"` or `"test"` |
| `block` | number | Block number, 1-indexed (practice is block 1) |
| `trial_index_in_block` | number | Position within the block, 1-indexed |
| `attempt` | number | 1, or more when a missed trial is repeated |
| `condition`, `transition` | `"common"` or `"rare"`, or null | The transition (null when the first choice was missed) |
| `planned_transition` | `"common"` or `"rare"` | The transition drawn for the trial, also when it did not happen |
| `stage1_choice` | `"A"` or `"B"`, or null | The first-stage option chosen (identity, not side); A usually leads to `red`, B to `blue` |
| `stage1_key`, `stage1_side`, `stage1_rt` | | The key, its side (`left` or `right`) and the RT of the first choice, ms |
| `stage1_left` | `"A"` or `"B"` | The first-stage option that was on the left |
| `stage2_state` | `"red"` or `"blue"`, or null | The state reached |
| `stage2_choice` | `"option_1"` or `"option_2"`, or null | The second-stage option chosen |
| `stage2_key`, `stage2_side`, `stage2_rt`, `stage2_left` | | As for the first stage |
| `stimulus_set` | string | The stimulus set's `name` (`"abstract_symbols"`, `"spaceship_planet_alien"`, or `"custom"` for a set without one) |
| `stage1_item_id`, `stage2_state_id`, `stage2_item_id` | string or null | The set's ids of the first-stage picture chosen, the state reached and the second-stage picture chosen (`"rocket"`, `"red_planet"`, `"green_alien"`); null when missed |
| `reward` | 0, 1 or null | Whether the chosen option paid a coin; null when a choice was missed |
| `reward_probs` | object | The reward probability of each option on this trial: `{ red: { option_1, option_2 }, blue: { ... } }` |
| `reward_walk` | string | The schedule, e.g. `random_walk sd=0.025 bounds=[0.25,0.75] boundary=reverse_step` |
| `common_transition_prob` | number | The probability of the common transition |
| `missed`, `missed_stage` | boolean, 1, 2 or null | A choice was missed, and which |
| `response`, `rt`, `timeout` | | The first choice's key and RT, and `timeout` = `missed`, so a battery-wide filter on `part: "response"` finds a response. `null` when missed |
| `response_window` | number or null | The window of this trial, ms |

**`choice` rows** have `stage` (1 or 2), `left` and `right` (the options on screen), `choice`, `side`, `state` (second stage), `stimulus_set`, the set's ids `left_item_id`, `right_item_id`, `chosen_item_id` and `state_id`, the native `response` and `rt` (`null` when missed), `timeout`, `response_window` and `condition`.

**`part` values the package writes:** `instruction`, `instruction_example`, `instruction_check`, `instruction_feedback`, `fixation`, `choice`, `acknowledgement`, `feedback` (the outcome; also `reward` and `running_total`), `timeout_message`, `response`, `iti`, `rest`, `manipulation_check_intro`, `manipulation_check`, `transition`, `completion`. `phase` is `instructions`, `practice`, `test` or `completion`. Display rows record the sampled duration as `duration_ms` and under the option's name without `_ms` (`fixation_duration`, `iti`, `feedback_duration`, `response_acknowledgement`, `timeout_message`).

## Scoring

```javascript
import { utils } from "@jspsych-timelines/two-step-task";

const scores = utils.scoring.getSummary(jsPsych.data.get());
const trials = utils.scoring.trialTable(jsPsych.data.get(), "test"); // one record per response row
```

Scores use the test phase's `response` rows. With no data, counts are `0` and every rate, mean and index is `null`. The stay measures use pairs of consecutive trials in the same block, and drop a pair when either trial has a missed choice.

| Metric | Description | Interpretation |
|---|---|---|
| `stay_common_rewarded`, `stay_common_unrewarded`, `stay_rare_rewarded`, `stay_rare_unrewarded` | Probability of repeating the first-stage choice, by the previous trial's transition and reward | A model-based learner stays after common rewards and rare non-rewards; a model-free learner stays after any reward |
| `n_stay_*`, `n_stay_pairs`, `stay_probability` | The number of pairs behind each probability, and the overall stay probability | |
| `mf_index` | (stay after reward) minus (stay after no reward), averaged over the two transitions | Positive: choices follow reward (model-free) |
| `mb_index` | ((common rewarded - common unrewarded) - (rare rewarded - rare unrewarded)) / 2 | Positive: choices use the transition structure (model-based) |
| `mb_rt_index` | Mean second-stage RT after rare minus after common transitions, ms | Positive: slower after surprising transitions (Shahar et al., 2019) |
| `total_reward`, `reward_rate` | Coins earned, and per completed trial | |
| `stage2_best_option_rate` | Share of second-stage choices of the option with the higher current probability (ties left out) | Learning of the second-stage values |
| `common_transition_rate` | Realised share of common transitions | |
| `stage1_mean_rt`, `stage2_mean_rt` | Mean RT of each stage, ms | |
| `n_trials`, `n_completed`, `n_missed`, `n_missed_stage_1`, `n_missed_stage_2` | Counts (`n_trials` includes repeated attempts) | |

The two indices are cell-mean contrasts on the probability scale, not the coefficients of the logistic regression of the literature. **Not in the package:** the logistic regression (and its hierarchical version), the hybrid reinforcement-learning model with the weight `w`, and RT-based models (DDM-RL). They need model fitting, which belongs in analysis, and the data has what they need (`trialTable`, or the `response` rows directly). A regression with the true reward probabilities as a predictor (S009) can use `reward_probs`.

**Exclusion is analysis, not the package.** The package never excludes anything. The criteria in the literature are for the analyst: Expfactory's credit rules (missed trials under 40%, median RT over 200 ms, key diversity under 85%), an abort after 6 missed trials (S026), and comprehension-quiz scores (S120, S138). The stay measures are unreliable with few trials (the split-half reliability of the model-based index was .41 at 25 trials and .71 at 300 in S062), so analysts should consider the number of usable pairs, `n_stay_pairs`.

## Translation

Pass a `text` object to replace interface strings; partial objects are merged with the defaults. The keys, from `src/text.ts`, where each function documents its named parameters:

- **Strings:** `instruction_correct`, `continue_button`, `fixation`, `too_slow`, `questionnaire_intro`, `task_complete`.
- **Functions** (they can only be set from code):
  - the instruction pages: `instruction_intro`, `instruction_response`, `instruction_transitions`, `instruction_drift`, `instruction_demo_intro`, `instruction_practice_intro`;
  - the walkthrough, each with a prompt, a hint after a wrong answer and the answer after the last attempt: `step_first`, `step_first_hint`, `step_first_reveal`, `step_second`, `step_second_hint`, `step_second_reveal`, `check_mapping`, `check_mapping_hint`, `check_mapping_reveal`, `check_statement`, `check_statement_hint`, `check_statement_reveal`; and `step_outcome`, `statement_transitions_true`, `statement_transitions_false`, `statement_drift_true`, `statement_drift_false`;
  - during and after the task: `instruction_test_intro`, `outcome_coin`, `outcome_none`, `running_total`, `block_complete`, `questionnaire_question`, `result_summary` (they take the set's reward noun);
  - `framing_words({ words, set })`, which returns the nouns of the cover story (`first`, `first_plural`, `second`, `second_plural`, `state`, `state_plural`, `reward`, `reward_plural`, and how each option and state is named in a sentence, `first_name` and `state_name`). The words come from the stimulus set (its `noun` and the `name` of its items and states); the default returns them unchanged. A translation returns its own words, by `set` (the set's name) if it translates more than one set.

The instruction functions receive the resolved options that change what they say (the key names, the time allowed, whether a missed trial is repeated, whether the options change places), so a translation can reproduce those sentences.

```javascript
createTimeline(jsPsych, {
  text: {
    too_slow: "Te langzaam",
    continue_button: "Verder",
    outcome_coin: () => "Je kreeg een munt",
    framing_words: ({ words }) => ({ ...words, reward: "munt", reward_plural: "munten" }),
  },
});
```

## Timeline Units

`timelineUnits` exports factories for the individual pieces. Most take the object from `timelineUnits.createContext(jsPsych, options)`: `createInstructions`, `createInstructionWalkthrough`, `createPracticeIntro`, `createTestIntro`, `createSchedule` (the generated plans of a phase), `createBlock`, `createTrial`, `createDisplayTrial`, `createTransition`, `createRestBreak`, `createQuestionnaire` and `createCompletion`. `utils.stimuli` holds the bundled stimulus sets (`abstractSymbols`, `spaceshipPlanetAlien`) beside helpers that work for any set: `setProblems` (what is wrong with a set, as messages), `prepareSet` (the set with its defaults filled in and keyed by role), and the renderers `renderItem`, `renderShip`, `renderOption`, `renderState`, `renderCoin`, `renderPair` and `paintDisplay`.
