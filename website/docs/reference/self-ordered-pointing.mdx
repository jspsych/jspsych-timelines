# Self-ordered pointing

Package: `@jspsych-timelines/self-ordered-pointing` ([source](https://github.com/jspsych/jspsych-timelines/tree/main/packages/self-ordered-pointing)). Version documented here: <code>{manifest['self-ordered-pointing'].version}</code>.

## Overview

Self-ordered pointing measures working memory for what you have already chosen, and the monitoring that goes with it. The participant sees a set of N items on a screen and picks one. The screen then changes: the same N items return in new places, and the participant picks again, and so on for N screens. The rule is to pick an item that has not been picked before in the set, so the only way to do it is to remember which items you already chose, not where they were. A pick of an item already chosen is a repeat error. Errors rise with set size, so the task is run with several sizes (6, 8, 10 and 12 items by default), several times each.

The task comes from Petrides and Milner (1982), who gave patients with frontal and temporal lobe lesions four self-ordered tasks, two verbal and two nonverbal. This implementation follows the computerised version of the TaskBeacon reference implementation (6, 8, 10 and 12 items, three series each, increasing set size, untimed, no feedback), which agrees with Inquisit's SOPT and the lab protocol of Geva et al. (2016). The recommended score is the total number of repeat errors (Ross et al., 2007).

**Canonical citation:** Petrides, M., & Milner, B. (1982). Deficits on subject-ordered tasks after frontal- and temporal-lobe lesions in man. *Neuropsychologia, 20*(3), 249-262. https://doi.org/10.1016/0028-3932(82)90100-2

## Task Description

**Terms.** A *series* is one run through a set: N pages of N items, one pick per page (the literature calls it a "trial"). A *page* is one screen of items and one scorable row. A *set size* is N.

**A page.** A blank screen (250 ms), then the N items in a grid. The grid is the stage: it stays at the vertical centre of the display and fits a 390 px wide phone and a 430 px tall run area. The participant clicks (mouse) or taps (touch) one item, and the next page follows. The pick is a position on screen; the package maps it to the item that sat there and decides from the series' history whether it is a repeat. After N pages the series is over. A page opens each series, so participants know the memory restarts. By default nothing marks the picked items and there is no feedback, as in the reference implementation.

**Items.** `stimulus_set.items` takes a stimulus set, which is data: the package's bundled sets are values in `utils.stimuli`, and your own set is the same shape. The bundled sets:

| Set | Items |
|---|---|
| `utils.stimuli.abstractDesigns` (default) | 48 random polygons (7 to 10 vertices, Attneave style), generated once with a seeded generator and committed as data, so every run draws the same pool. The designs of Petrides and Milner (1982) are not used, because their licence is unclear. |
| `utils.stimuli.representationalDrawings` | 48 outline drawings of nameable everyday objects (animals, food, tools, household items, vehicles, clothing, instruments), from the [Lucide](https://lucide.dev) icon set (ISC licence). They are icon-style line drawings, not a normed picture set: the Snodgrass and Vanderwart style sets used in the literature have no open licence, and Inquisit's drawings (S024) are proprietary. |
| `utils.stimuli.words` | 48 common concrete nouns |
| `utils.stimuli.nonwords` | 48 pronounceable nonwords |

Your own set is `{ name, noun, items }`, or just the array of items. An item is a string (a text item) or an object with one of `text`, `image` (a URL) or `svg` (SVG markup), and an optional `id`, which the data records as `chosen_item_id` (the default is the text, or the set's name and the item's position). `name` is recorded as `stimulus_set` on every pick row. `noun` (`{ singular, plural }`) is what the instructions call the items; without it they say "word" for a set of text items and "picture" otherwise. The order of `items` matters for `pool: "nested_first_n"`, which takes the first N. In a preset or a shared link, which are JSON, a bundled set is written `{ "$util": "stimuli.words" }`, and the Code view shows it as `utils.stimuli.words`.

**Which items each set has.** `stimulus_set.pool`: `"nested_first_n"` (default, as in the reference implementation) makes every set the first N items of the pool, so a set of 6 is contained in the set of 12; `"distinct_per_set_size"` gives every set size its own items (Geva et al., 2016; Johnson et al., 2024), so no item reappears across sizes. The items of a set size are the same in all its series; only their positions change.

**Rearrangement.** `rearrangement_rule: "full_reshuffle_each_page"` (default) draws a new random arrangement on every page, never the one before. `"partial_reshuffle_each_page"` moves only some of the items after each pick (Cox et al., 2014); the share is `reshuffle_proportion` (default 0.5, at least two items move), because the paper says only "some". The layout is `"fixed_grid_slots"` (rows and columns follow the set size: 6 is 2 by 3, 12 is 3 by 4) or `"free_positions_in_area"` (each item at a random place inside its own cell, so no two overlap).

**Position-repeat rule.** Some studies tell participants not to point to the same screen position more than twice in a row, because a position strategy replaces remembering items. `position_repeat_rule` (task-specific, because `sequence_constraints` orders generated trials, not the participant's picks): `"none"` (default), `"instructed"` (an instruction page, Geva et al.), `"enforced"` (the position that would break the limit is switched off for the page, S055), `"detect_and_remind"` (the pick is allowed and a reminder follows, S024). `position_repeat_max` is the limit (default 2). The rule needs the fixed grid.

**Set sizes and design.** `set_sizes` (default 6, 8, 10, 12) and `trials_per_condition` (series per set size, default 3) make the design. `block_order` sets the order: `"ascending"` (default) and `"descending"` make one block per set size; `"fixed"` the same in the order of `set_sizes`; `"random"` one block holding every series in random order (per participant); `"random_within_block"` `trials_per_condition` blocks, each holding one series of every size in random order. `set_sizes` and `block_order` apply to the test only: practice uses `practice.set_sizes` (default one set size of 3), and `practice_trials` practice series (default 0, as in the reference implementation).

**Walkthrough and practice.** The instruction pages are followed by an interactive walkthrough on a set of three, with the task's own items and grid: pick any item; the items move; pick one you have not picked yet; pick the one that is left. A repeat shows a hint and the step repeats with the items moved again, up to 3 times, after which the item that was not picked is shown and the walkthrough moves on. Practice (if `practice_trials` is above 0) shows "New" or "Picked before" after each pick by default, so the rule is learned; the test shows nothing.

**Timing.** The task is untimed in every source (`response_window_ms: null`). A number or `{min, max, step}` limits each pick; a miss records no pick (`timeout: true`, `response: null`), the page is not repeated and the item stays unpicked.

**Not implemented (throws, naming the option).** `adaptive` other than null (S040's IRT-CAT, S056's ascending-until-fail), `error_correction_procedure` other than `"none"`, `population_protocol` other than `"standard"` (the preschool protocol needs picture cards, pre-training and a discontinue rule that the spec gives no count for), `response_device` other than mouse and touch, keyboard and other devices, `trial_feedback` other than `"accuracy"` and `"none"`, `block_order: "counterbalanced" and `"alternating"`. The language of the instructions is the `text` option (see Translation).

## Examples

Fewer, different set sizes with separate items per size and a touch screen (Johnson et al., 2024):

```javascript
const { timeline } = createTimeline(jsPsych, {
  set_sizes: [4, 6, 8, 10],
  practice_trials: 3,
  response_device: "touch",
  stimulus_set: { pool: "distinct_per_set_size" },
});
```

A Petrides and Milner style position rule, enforced by the program, with words:

```javascript
const { createTimeline, utils } = jsPsychTimelineSelfOrderedPointing;
const { timeline } = createTimeline(jsPsych, {
  stimulus_set: { items: utils.stimuli.words },
  position_repeat_rule: "enforced",
  position_repeat_max: 2,
});
```

Your own pictures, with their own ids, and the instructions calling them "photos":

```javascript
const { timeline } = createTimeline(jsPsych, {
  stimulus_set: {
    items: {
      name: "my_photos",
      noun: { singular: "photo", plural: "photos" },
      items: [
        { id: "beach", image: "img/beach.jpg" },
        { id: "forest", image: "img/forest.jpg" },
        // ... at least as many as the largest set size
      ],
    },
  },
});
```

Each block holds every set size once in random order, three blocks, with a 6 s limit per pick:

```javascript
const { timeline } = createTimeline(jsPsych, {
  set_sizes: [3, 6, 9, 12],
  trials_per_condition: 3,
  block_order: "random_within_block",
  response_window_ms: 6000,
});
```

## Data Output

Every row carries `task: "self-ordered-pointing"` and `task_version`. **The scorable row is one pick** (`phase: "test"`, `part: "response"`, one per page). Practice picks are `phase: "practice"`, `part: "response"`.

`phase` values: `instructions`, `practice`, `test`, `completion`. `part` values the package writes:

| `part` | Rows |
|---|---|
| `instruction` | Instruction pages, and the pages before the practice and the test |
| `instruction_check` | Walkthrough: one pick, with `condition` (`first`, `new`, `last`), `attempt` and the pick fields below. Never scored |
| `instruction_feedback` | Walkthrough: confirmation, hint, or the revealed item (`feedback_kind`, `revealed_item_id`) |
| `transition` | The page that opens a series (`series`, `set_size`) |
| `iti` | The blank before each page (`iti`, `duration_ms`) |
| `response` | **One pick: the scorable row** |
| `feedback` | Page feedback (`feedback_kind: "accuracy"`, `feedback_duration`, `correct`) |
| `reminder` | The position reminder (`position_repeat_rule: "detect_and_remind"`) |
| `completion` | The last screen |

**Pick row (`response`).** Where it is: `block` (1…n; practice is block 1), `trial_index_in_block` (1-based position of the series in its block; in the grouped orders this is the series number within its set size), `series` (1-based in the phase), `set_size`, `set_size_trial` (the series' number among those of its set size), `choice_index` (the page within the series, 1…`set_size`). What was picked: `chosen_item_id` and `response` (the same, `null` on a timeout), `chosen_position` (1-based slot, row by row), `chosen_row`, `chosen_col`, `item_arrangement` (the item id in each slot on this page), `item_offsets` (free positions only), `previous_item_id` (the item picked on the page before, `null` on page 1 or after a timeout). Correctness from the history: `n_picked_before`, `is_repeat_error`, `correct` (a new item was picked: false for a repeat and for a timeout). The position rule: `same_position_run` (consecutive picks at this slot, including this one), `position_rule_violation` (the run exceeds `position_repeat_max`, when the rule is not `"none"`), `disabled_position` (the slot switched off under `"enforced"`). Timing: `rt`, `timeout`, `response_window`. Setup: `stimulus_set` (the set's `name`, `"custom"` without one), `stimulus_layout`, `rearrangement_rule`, `response_device`. `trial_index` is jsPsych's.

## Scoring

`utils.scoring.calculateScores(data)` filters on `task`, `phase: "test"` and `part: "response"`, so other tasks' rows, practice and the walkthrough are ignored. Empty data gives 0 for counts and `null` for means and proportions, and empty lists.

| Field | Meaning |
|---|---|
| `total_errors` | Repeat picks over all series and set sizes. The recommended score (Ross et al., 2007) |
| `mean_errors_per_series` | `total_errors` / `n_series` (Cox et al., 2014 averaged over the three series) |
| `errors_by_set_size` | Per set size: `n_series`, `errors`, `mean_errors_per_series` (Geva et al., 2016: the load function) |
| `error_rate_by_choice_order` | Repeat rate by page within the series (the first page cannot repeat) |
| `mean_accuracy` | Proportion of picks that were new items (Sturm et al., 2026) |
| `span_before_first_error` | Mean over series of the correct picks before the first repeat; a series with no repeat counts all its correct picks, so a timeout lowers it (Johnson et al., 2024) |
| `max_set_size_completed` | Largest set size with a series in which every page picked a new item: no repeat and no timeout (Silman et al., 2022) |
| `perseverative_errors` | Repeats of the item picked on the page just before |
| `n_timeouts`, `n_picks`, `n_pages`, `n_series` | Counts |
| `mean_rt` | Mean RT (ms) of the picks |
| `n_position_repeat_violations` | Picks that broke `position_repeat_max` |

Scoring methods in the spec that are not computed: points by set-size level (the preschool protocol, S056), the IRT 3PL load and guessing model (S040) and the chance-corrected selection statistic (Gillett, 2007). The first two need the child and adaptive protocols; the dossier gives no formula for the third. The rows carry the fields they need (`set_size`, `choice_index`, `is_repeat_error`).

The package does not exclude participants. The literature gives no cutoff to apply on repeat errors; report them as they are. Test-retest reliability of the total error score is .82, of the span score .58 and of perseverations .12 (Ross et al., 2007; N = 93, about 43 days apart, from the abstract), with a practice effect of d = .34.

## Translation

Pass `text` with any of the keys below; unspecified keys keep their defaults. Keys marked (fn) are functions of a named-parameter object (see the doc comments in `src/text.ts`):

`instruction_intro` (fn), `instruction_rule` (fn), `instruction_position_rule` (fn), `instruction_time_limit` (fn), `instruction_demo_intro` (fn), `instruction_step` (fn), `instruction_hint` (fn), `instruction_reveal` (fn), `instruction_correct`, `instruction_demo_done` (fn), `practice_intro` (fn), `test_intro` (fn), `series_intro` (fn), `feedback_new`, `feedback_repeat`, `position_reminder` (fn), `item_button_label` (fn), `continue_button`, `task_complete`, `result_summary` (fn).

The instruction functions receive the noun for the items (`noun`, `nouns`: "design", "word", ...) and the verb for the response (`verb`: "click" or "tap"), so a translation can follow the configured item set. The language of the instructions in the spec (Chinese, Portuguese, French) is this option; no translation is bundled.

```javascript
createTimeline(jsPsych, {
  text: {
    continue_button: "Weiter",
    feedback_new: "Neu",
    feedback_repeat: "Schon gewählt",
    series_intro: ({ series, n_series, set_size, nouns }) =>
      `<h2>Satz ${series} von ${n_series}</h2><p>${set_size} ${nouns}. Wählen Sie jedes einmal.</p>`,
  },
});
```

## Timeline Units

`timelineUnits` holds `createContext`, `createInstructions`, `createInstructionWalkthrough`, `createTestIntro`, `createPickTrial` (one page: the grid of items and one pick), `createDisplayTrial`, `createSeries` (a series from a plan), `planSeries` (the series of a phase), `createPractice`, `createTest` and `createCompletion`. Most take the object from `createContext(jsPsych, options)`. `utils` holds `scoring`, `constants`, `text`, `stimuli` (the bundled stimulus sets), `items` (`buildPool`, `assignItems`, `gridDims`, `nextArrangement`), `sequence` (`scheduleBlocks`, `practiceSetSizes`), `simulation` (the simulated participant, below) and `options` (`resolveOptions`, `validateOptions`).

**Simulation.** `jsPsych.simulate(..., "data-only")` answers every page with a simulated participant who recognises each earlier pick as picked with a probability that falls with set size (0.97 at 3 items, 0.88 at 6, 0.7 at 12) and picks at random among the items it does not recognise as picked, so repeat errors rise with set size and within a series. The simulated pick is a slot: it goes through the same code as a click, which finds the item, checks the history and writes the row. The walkthrough is answered correctly.
