# Stop-signal task defaults: where they come from and what was changed

The anchor is the STOP-IT jsPsych version (Verbruggen, commit 73e4654, S010), picked by the spec generator (typicality 0.85, coverage 0.95, lead 0.50 over the runner-up S070, no escalation). The consensus guide (S001, Verbruggen et al., 2019) supplies the scoring and the recommendations the instructions follow. Nothing here needed a human tie-break, but four defaults are marked **needs human decision**.

What STOP-IT does (S010): a left or right arrow after a 250 ms fixation; on 25% of the trials (2 of every 8, "design cycles") the arrow turns red after the stop-signal delay (SSD); the arrow and the red arrow stay until a response or 1250 ms; 500 ms ITI; the SSD is a 1-up/1-down staircase that starts at 200 ms, moves by 50 ms and is kept between 50 and 1200 ms, tracking 50% successful stops, and it is not reset between phases or blocks; 4 test blocks of 64 trials with a performance summary and a 15 s break; 32 practice trials with feedback; instructions tell participants not to wait for the signal and explain the tracking; left and right arrow keys; fullscreen, a window of at least 800x600, no Safari.

## Defaults changed from the spec

| Option | Spec default (basis) | Package default | Reason |
|---|---|---|---|
| `adaptive.procedure` | `tracking` (anchor, 4 of 4 sources that report a procedure) | `"staircase_1up_1down"` | "tracking" is not a value of the vocabulary's `procedure` enum. In all four sources it is a 1-up/1-down staircase on the SSD that tracks 50% successful stops, which is `staircase_1up_1down` with `target_accuracy: 0.5`. The other implemented values are `staircase_1up_2down` and `_3down` (2 or 3 successful stops in a row lengthen the delay; they converge near 0.707 and 0.794). `ascending_discontinue`, `quest` and `rt_based` throw. |
| `adaptive.step_size` | `50` | `50`, resolved to `{ up: 50, down: 50 }` | A single number is the larger step; the other follows from `target_accuracy` so the delay is stable at that stopping rate (p x up = (1 - p) x down). With `{ up, down }` the target is derived (S082: 25 and 50 give 0.667); stating both and disagreeing throws. |
| `adaptive.bounds` | `1200` (a lone number: the spec merged `ssd_min_ms` and `ssd_max_ms` into one key, and the later one won) | `[50, 1200]` | `ssd_min_ms` is 50 in the same source. `bounds` is `[min, max]` with `null` for no limit (S085 has no maximum). |
| `adaptive.tracks`, `adaptive.reset` | not in the spec (the translations predate them; the structure and reset rows are untyped) | `"single"`, `"never"` | STOP-IT: one global staircase, "continuous" (practice carries into the test). `tracks: "per_condition"` keeps one staircase per go direction (see below); `reset: "phase"` is S082's reset per phase. |
| `trial_feedback` | `none` (anchor, "practice_only" in the dossier) | `"none"`, with `practice: { trial_feedback: "accuracy" }` | STOP-IT gives feedback in practice only. A practice default applies unless `trial_feedback` is set at the top level or in `practice`. Accuracy only: no RT (the standard's default for feedback; STOP-IT's practice feedback has none either). |
| `sequence_constraints` | `{ cycle_length: 8 }` | `{ cycle_length: 8 }` where it fits, otherwise none | The cycle rule needs blocks of whole cycles that carry the proportions exactly (0.25 x 8 = 2). With 0.2 or 0.3 stop trials, or 60 trials per block, it cannot hold, so the default becomes a shuffled list with exact block counts. A `cycle_length` you give that does not fit throws. This makes the default depend on other options, and the spec has no way to say so. |
| `condition_proportions` | `{ stop_signal_probability: 0.25, stop_probability_blocks: null }` | `{ stop: 0.25, go: 0.75 }` | The standard's own keys (the task's trial types). A single map is a list of one; a list gives one map per block, the last repeating (the spec's block-wise values, S011 and S098, are untyped). |
| `n_test_trials` | not in the spec | `n_blocks x trials_per_block` (256) | The Quick demo and the standard's count checks use `n_test_trials`. Given alone it sets `trials_per_block`; given with all three it must agree. |
| `strategy_instruction` | untyped (`dont_wait_plus_tracking_explanation`; the vocabulary only lists `none`) | `"dont_wait_plus_tracking_explanation"`, or `"dont_wait"` when the delays are fixed | The anchor says not to wait and explains that the signal moves with performance. S001 recommends it. With fixed delays the explanation would be false, so an unset value becomes `dont_wait`; setting the explanation explicitly with fixed delays throws. The dossier's values are used as they are; the vocabulary needs `dont_wait`, `dont_wait_plus_tracking_explanation` and `balance_speed_and_stopping`. |
| `device_eligibility` | `browser_restricted` (anchor: fullscreen, 800x600 window, Safari excluded) | `"none"` | The anchor's rule has three parts a jsPsych timeline cannot enforce: fullscreen, window size and a browser exclusion (excluding a browser by name is not defensible). `browser_restricted` and `hardware_required` throw. Decided (2026-11-16): `none` stays the default; `computer_only` is available. |
| `stimulus_set` | `{ go: "left/right arrows", stop signal: "go arrow turns red" }` | `{ go: "arrows", stop_signal: "arrow_turns_red" }` | Typed names for the forms the package draws (`arrows`, `arrows_in_circle`; `arrow_turns_red`, `circle_turns_red`, `border`, `tone`). Role keys are the task's own (`stop_signal`, not `stop signal`). The other forms in the dossier (shapes, pictures, a flower, a star outline, a square in degrees) are not drawn. |
| `stimulus_duration_ms` | `null` (go) and `null` (stop signal) as two components | `{ go: null, stop_signal: null }` | The vocabulary has one `stimulus_duration_ms`; the dossier has two durations. A number or `null` is the go stimulus (the vocabulary's reading), the map sets both. A signal duration of `null` stays until the trial ends (the tone lasts 75 ms, S057). |
| `stimulus_modality` | `{ stop signal: "visual" }` | `"visual"` | The vocabulary's enum has no roles; the option is the modality of the stop signal. `"auditory"` needs the `tone` signal (and sets it when `stop_signal` is not given). |
| `break_duration_ms` | `15000` | `15000` | Kept. `null` is self-paced, a number enables the continue button after that long, `0` is no rest screen. |
| `instruction_demonstration` | not in the spec | `"interactive"` | PACKAGE-STANDARD §6a. Two go steps and one stop step (the signal after 250 ms, 2.5 s of waiting). |
| `practice_criterion` | `null` (anchor) | `null`; when given, `accuracy` defaults to 0.8, `window` to the whole block, `on_fail` to `"repeat"`, `max_repeats` to 2 | The vocabulary's fields are `accuracy`, `window`, `on_fail`, `max_repeats`. The spec typed the sources' criteria with other names (`go_accuracy_min`, `go_rt_median_max_ms`, `stop_accuracy`); only go accuracy is expressible. Decided (2026-11-16): "accuracy" for this task. The package takes go accuracy (omissions and wrong keys count as errors) over the last `window` practice trials. Stop trials do not count, because their outcome depends on the staircase. S011 and S086 use go accuracy 0.8 and 0.7. |

## Choices the spec leaves open

- **`adaptive.tracks: "per_condition"`: what is a condition?** The vocabulary says the trial's condition picks the staircase (a stop-signal delay per stimulus). The stop-signal task has two trial types, go and stop, and stop trials are one condition. S072 uses a staircase for each combination of modality and stimulus category, which this task has no factor for. Decided (2026-11-16). The package keys the staircases by the go direction (left, right): independent, the trial's own go stimulus picks it, and it needs no factor the options do not have. A factor for stimulus category (S072) or block type (S011's reset per condition) would take a crossed-factor `condition_proportions`.
- **`adaptive.reset` and practice.** `"never"` carries the practice staircase into the test (STOP-IT's "continuous"); `"phase"` starts the test fresh at `start_level`; `"block"` starts every block, practice included, fresh. A practice override with a different `adaptive` never carries over. Each is a new `jsPsych.adaptive` staircase, not a rewind.
- **A finished staircase.** With `discontinue_rule`, a staircase that is done keeps its last delay and the data say so (`staircase_state.done`). No source in the dossier uses one, so there is no anchor value (default `null`).
- **Premature responses.** A response before the signal appears (RT below the delay) is a failed stop, counts in p(respond | signal) and moves the staircase down; `stop_signal_shown` is false. This is the consensus guide's rule.
- **`response_window_ms`.** Null (untimed) throws: a stop trial has no response to end it. The window runs from go onset and includes the stop signal.
- **Timing of the signal.** The signal is scheduled half a frame before the delay and drawn on the next animation frame, so it lands on the frame nearest the delay; `ssd_actual` is that measured time. Data-only simulation draws nothing, so `ssd_actual` is `null` there. Browser timing was not verified against external hardware.
- **Counterbalancing.** `response_mapping_counterbalancing` only accepts `"fixed"`. The arrows point left or right, so the mapping is spatial; random assignment only makes sense for non-spatial stimuli (S011's four shapes), which are not drawn.
- **Colours.** The spec has no `stimulus_color`. The stage is white on black with a red or blue signal, fixed.
