Operation span (complex span)

Package: @jspsych-timelines/operation-span (source). Version documented here: 0.0.1.

Overview​

Complex span tasks measure working memory capacity by interleaving a processing task with items to remember. In the operation span the participant checks simple arithmetic ("(2 × 3) + 1 = 7: true or false?") between letters to remember, then recalls the letters in order. The score is how many letters were recalled in the correct position, with the math task there to prevent rehearsal. Reading, symmetry and rotation span use other processing tasks and other memoranda; only the operation span is implemented (task_variant: "operation_span").

This implementation follows the automated operation span of the Engle lab (Unsworth, Heitz, Schrock & Engle, 2005) with the recommendations of Conway et al. (2005): each participant's time limit for the math problems is set from their own practice speed (mean + 2.5 SD), set sizes are random per participant, and the recommended score is partial credit.

Canonical citation: Unsworth, N., Heitz, R. P., Schrock, J. C., & Engle, R. W. (2005). An automated version of the operation span task. Behavior Research Methods, 37(3), 498-505. https://doi.org/10.3758/BF03192720

Task Description​

Each test trial is a sequence of steps, one per letter to remember. A step is a math problem followed by a letter (shown for 800 ms). By default the problem comes first on its own ("(4 ÷ 2) − 1 = ?"); the participant solves it in their head and clicks "Solved", then sees a proposed answer ("2") and clicks True or False. The first screen is timed (see below); the answer screen is not. After the last step a recall screen shows a 4 × 3 matrix of letters. The participant clicks the letters in the order they were shown, with a Blank button for a letter they cannot remember and Clear to start again, then Done. Feedback (letters recalled, math errors, running math accuracy) follows for 2 s.

The calibrated deadline. The anchor sets each participant's time limit for the problem screen to the mean plus 2.5 standard deviations of their correct solution times in a processing-only practice. In this package that is the default value of response_window_ms, a function: utils.deadlines.meanPlusSd(2.5). It runs at the start of every timed processing trial, reads the correct processing-only practice rows itself, and returns the same value every time once practice is over. With fewer than 5 usable practice RTs it returns the fixed 6000 ms. The value used and the rule's label are recorded on every processing row (response_window, response_window_rule, which also says how many practice RTs the helper used, or that it fell back to 6000 ms). Other rules: utils.deadlines.meanPlusSd(2), utils.deadlines.percentile(95), each with optional { min, max } bounds, or any function ({ jsPsych, phase, block, trial_index_in_block }) => ms | null. A fixed deadline is a number (6000), no deadline is null. Function values are code-only: the docs form leaves them out and presets that reproduce a study with a calibrated deadline do not set the option.

Practice and instructions. Instructions are followed by an interactive walkthrough: a true and a false problem answered in the task's own format, then a two-item recall at task timing on the real recall input. A wrong answer shows a hint and repeats the step, up to 3 times. Practice then has three parts (practice_structure): letters only (4 trials), processing only (15 problems, self-paced, with per-problem feedback; they calibrate the deadline), and combined (3 trials of set size 2, at the calibrated deadline). practice_criterion can require a processing accuracy before practice ends. Then the test: 3 trials of each of the set sizes 3 to 7, in random order per participant.

Set sizes and block order. set_sizes, trials_per_condition and n_test_trials describe the same design (15 = 5 sizes × 3) and are reconciled: give one and the others follow, give inconsistent ones and it throws. block_order sets the order: "random" (one block, shuffled per participant), "random_within_block" (one block per repetition, each holding every set size once in random order), "fixed" (the same interleaved order for everyone), "ascending", "descending". A list of lists in set_sizes gives each block its own set sizes. Practice set sizes are practice.set_sizes (default [2]), never the test's.

Memoranda. stimulus_set.memorandum takes a stimulus set, which is data: the package's bundled sets are values in utils.stimuli, and your own set is the same shape. The bundled sets:

SetItems
utils.stimuli.letters (default)The 12 consonants of the Engle-lab automated span, F H J K L N P Q R S T Y (Unsworth et al., 2005)
utils.stimuli.digits1 to 9 (S020)
utils.stimuli.words16 common English nouns, a stand-in for the word studies (S034, S043), whose lists are not reported

Your own set is { name, noun, items }, or just the array of items. An item is a string or an object { text, id }; the data records the text and the id (default: the text). Memoranda are text, because recall names them: the matrix labels its buttons with them, typed and key-press recall match what is entered against them (ignoring case and surrounding spaces, so two items may not differ only in case), and the feedback lists them. An image or svg item throws. name is recorded as stimulus_set on memorandum and recall rows ("custom" without one). noun ({ singular, plural }) is what the instructions and the recall prompt call the items; without it they say "item". The recall matrix shows the whole set, in the order of items, four to a row. The set needs at least as many items as the largest set size (and 2, for the walkthrough), and key-press recall needs one-character items. No word list is bundled: the studies that used words (S034, S043) do not report their lists, so their presets carry a stand-in list of 16 English words and say so; supply your own. In a preset or a shared link, which are JSON, a bundled set is written { "$util": "stimuli.digits" }, and the Code view shows it as utils.stimuli.digits.

Other options. Problems per memorandum (0 gives a simple span), memorandum before the problem, a single-screen problem format, typed recall (one box per item) or key-press recall, free recall order, blank, skip or ? as the omission, mouse, touch or keyboard for the processing task and for recall separately.

Try it​

For a short run, pick "Quick demo" in the Preset menu (the walkthrough, 2 letters-only, 6 processing-only and 2 combined practice trials, then 4 test trials) and press Run. The other presets are study configurations from the literature; those that used a calibrated deadline leave response_window_ms out, so the calibrated default applies. The task runs from the bundle built from this repository. The options are kept in the URL hash, so you can share a configuration.

Examples​

A fixed 6 s deadline (as in S021 and S026) and shorter set sizes:

const { timeline } = createTimeline(jsPsych, {
  set_sizes: [2, 3, 4, 5],
  response_window_ms: 6000,
  processing_display_format: "equation_with_answer_single_screen",
  stimulus_duration_ms: 1000,
});

Each block holds every set size once, in random order, three blocks:

const { timeline } = createTimeline(jsPsych, {
  set_sizes: [3, 4, 5, 6],
  trials_per_condition: 3,
  block_order: "random_within_block",
});

The calibrated deadline with a different rule and bounds, and an 85% practice criterion with one repeat:

const { timeline } = createTimeline(jsPsych, {
  response_window_ms: utils.deadlines.meanPlusSd(2, { min: 2500, max: 8000 }),
  practice_criterion: { accuracy: 0.85, window: 10, on_fail: "repeat", max_repeats: 1 },
});

Digits instead of letters (the recall matrix shows 1 to 9):

const { timeline } = createTimeline(jsPsych, {
  stimulus_set: { memorandum: utils.stimuli.digits },
});

Typed recall of your own words with the keyboard; the instructions call them "words" and the data records the set's name:

const { timeline } = createTimeline(jsPsych, {
  stimulus_set: {
    memorandum: {
      name: "concrete_nouns",
      noun: { singular: "word", plural: "words" },
      items: ["apple", "bread", "chair", "dance", "eagle", "flame", "grape"],
    },
  },
  set_sizes: [2, 3, 4],
  response_device: { processing: "keyboard", recall: "keyboard" },
  response_format: "free_text",
  response_order: "free",
});

Data Output​

Every row carries task: "operation-span" and task_version. The scorable row is the recall (phase: "test", part: "response", one per span trial). Processing and memorandum rows are separate parts of the same trial.

phase values: instructions, practice, test, completion. part values the package writes:

partRows
instructionInstruction and transition pages
instruction_exampleWalkthrough: the problem screen, the memoranda of the recall step, and the static examples
instruction_checkWalkthrough: a problem answered, or a recall, with condition, attempt, correct. Never scored
instruction_feedbackWalkthrough: confirmation, hint, or the revealed answer (feedback_kind)
memorandumA memorandum shown (memorandum (its text), memorandum_id, stimulus_set (the set's name), position, stimulus_duration, duration_ms)
inter_itemThe gap between events within a trial (inter_item_interval, duration_ms)
processing_problemTwo-screen format: the timed problem screen (rt is the solve time, timeout, response_window)
processingOne row per processing episode, in every display format (see below)
responseThe recall: the scorable row
feedbackTrial feedback (feedback_kind, feedback_duration)
completionThe last screen

Recall row (response). set_size, stimulus_set (the memorandum set's name), presented_items and presented_item_ids, recalled_items (as entered; null for a blank) and recalled_item_ids (the item each entry names; null for a blank or typed text that is no item), recall_correct_positions (one boolean per presented position), n_correct_positions, proportion_correct, perfect and correct (every position right), recall_rt, response_order, response_format, response_device (recall), processing_n, processing_errors, processing_timeouts (null in letters-only practice), practice_part (practice only), block (1…n; practice is block 1) and trial_index_in_block (1-based). trial_index is jsPsych's.

Processing row (processing). problem, shown_answer, answer_is_true, correct_response, response, correct (verified correctly and in time), timeout (deadline missed: a speed error), rt (the timed response: the solve time in the two-screen format, the true/false response in the single-screen format; null after a timeout), solve_rt, verify_rt (two-screen format), response_window (the deadline in force in ms, null if none), response_window_rule ("fixed", "none", "self-paced", "jitter", a prebuilt helper's label with how it applied, such as "mean + 2.5 SD of correct practice RTs (n = 15)" or "mean + 2.5 SD of correct practice RTs: fixed 6000 ms fallback, 3 of 5 usable practice RTs", or "custom function"), response_device, set_size, position (memorandum step), episode, practice_part, practice_attempt. After a missed deadline in the two-screen format the answer screen is skipped and a brief "Too slow" notice is the row.

practice_part is "storage" (memoranda only), "processing_only" or "combined". The calibrated deadline reads the correct processing_only rows.

Scoring​

utils.scoring.calculateScores(data) filters on task, phase: "test" and the part, so other tasks' rows and practice are ignored. Empty data gives 0 for counts and sums and null for means and proportions.

FieldMeaning
partial_credit_unitMean over trials of the proportion of letters in the correct position (Conway et al., 2005). The recommended primary score
partial_credit_loadLetters recalled in the correct position, summed over trials (the Engle lab "partial score", 0 to 75 for the defaults)
absolute_scoreSummed set sizes of the trials recalled perfectly
n_perfect_trials, all_or_nothing_unitPerfect trials, and their proportion
processing_accuracyProportion of problems solved correctly and in time (a speed error counts as an error)
speed_errors, accuracy_errors, processing_errorsMisses of the deadline, wrong answers, and both
mean_processing_rtMean timed RT of correct problems
n_trials, total_items, n_processingCounts

The package does not exclude participants. Unsworth et al. (2005) drop participants below 85% processing accuracy; apply that, or another rule, to processing_accuracy in the analysis.

With response_order: "free" a position counts when its item was entered anywhere. Entries are compared with the items without regard to case or surrounding spaces. Walkthrough and practice rows are never scored.

Translation​

Pass text with any of the keys below; unspecified keys keep their defaults. Keys marked (fn) are functions of a named-parameter object (see the doc comments in src/text.ts); every text that names the memoranda gets noun and nouns from the set:

instruction_intro (fn), instruction_processing (fn), instruction_recall (fn), emphasis_speed, emphasis_accuracy (fn), emphasis_both (fn), read_aloud, instruction_demo_intro, instruction_examples_intro, instruction_step (fn), instruction_hint (fn), instruction_reveal (fn), instruction_correct, practice_storage_intro (fn), practice_processing_intro, practice_combined_intro, instruction_test_intro (fn), practice_repeat (fn), practice_failed, continue_button, ok_button, done_button, solved_button, true_button, false_button, blank_button, skip_button, clear_button, solve_prompt (fn), verify_prompt (fn), recall_prompt (fn), recall_box_label (fn), correct_feedback, incorrect_feedback, timeout_feedback, recall_feedback (fn), feedback_correct_answer (fn), task_complete, result_summary (fn).

createTimeline(jsPsych, {
  text: {
    done_button: "Listo",
    true_button: "Verdadero",
    false_button: "Falso",
    recall_feedback: ({ n_correct, set_size }) => `<p>Recordaste ${n_correct} de ${set_size}.</p>`,
  },
});

Timeline Units​

timelineUnits holds createContext, createInstructions, createInstructionWalkthrough, createTestIntro, createTransition, createMemorandum, createInterItem, createProcessing (one processing episode, in the configured display format), createRecall, createRecallFeedback, createProblemFeedback, createSpanTrial, planTrial, createPracticePart, createPractice, createTest and createCompletion. Most take the object from createContext(jsPsych, options). utils holds scoring, constants, text, deadlines, stimuli (the bundled sets letters and digits, and generateProblem), items (buildPool: a set's items as { id, text }), sequence (scheduleBlocks, fixedOrder, practiceSetSizes) and options (resolveOptions, validateOptions).
